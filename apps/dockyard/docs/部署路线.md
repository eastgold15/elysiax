1. 本地部署：读本地文件夹 → 本地构建 → 产物送服务器
这个模式本质上是 build locally, ship artifact。

流程大致是：

text
本地源码目录
   ↓ 读取（本地文件系统直接访问）
执行构建（本地 Node/Go/Java 工具链）
   ↓
构建产物（dist / jar / 二进制 / 静态文件）
   ↓
打包成 docker 镜像 或 直接 rsync/scp 到服务器
   ↓
服务器 docker run / docker compose up
优点：

构建环境在你本地，依赖、缓存、工具链都可控。

不需要服务器有完整源码和构建工具链，服务器只负责“跑”。

构建失败在本地就能发现，反馈快。

注意点：

产物和运行环境要匹配：本地是 macOS/ARM，服务器是 Linux/AMD64，直接送二进制会挂。所以用 docker 镜像形式是对的，镜像里带运行时，屏蔽差异。

镜像怎么送到服务器：

小规模：docker save → scp → docker load

正规：推到镜像仓库（registry），服务器 docker pull

构建产物里不要带本地路径/密钥：本地构建容易把 .env、绝对路径打进去，要做清理。
