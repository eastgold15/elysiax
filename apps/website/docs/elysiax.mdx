# elysiax

Bun + Elysia 2 + htmx（服务端 TSX）+ Solid client 逃生舱的全栈框架。**一棵目录树 `src/pages/`，页面文件夹内聚前端与后端**（整页、hx 片段、写端点、DI、service、repository、可选 Solid client），URL = 文件夹路径。InferDI 容器装配服务，codegen 把所有声明粘成类型安全的整体。

交互模型是混合的，且**渲染器单选**（[契约 §1.3](./module-contract.md)）：**htmx 管页面和表单**（服务端渲染，端点只吐 HTML 片段），**Solid client 页管复杂交互区**（如画布，端点只吐 JSON，Eden 消费）——一个原子选一种渲染器，两者永远不操作同一个 DOM 元素。设计哲学见[逐级降级](./lowering.md)：人只操作抽象，构建链把抽象降级成落盘的原料，每级产物可审查。

## 特点一览

| 特性 | 说明 |
| --- | --- |
| 页面即目录 | `<name>.page.tsx` / `.partials.tsx` / `.actions.ts` / `.di.ts`，URL = 文件夹路径，零路由配置 |
| 一端点两响应 | 无 `HX-Request` → AppLayout 整页；有 → 只渲染 content 片段。页面函数零 if/else |
| 写操作三态 | `ctx.redirect` / `ctx.toast` / `ctx.formError`，303 vs HX-Redirect、422 回显由框架分流 |
| 类型化 DI | `provide(Class, [Deps])` 依赖写类引用，类型从构造函数签名推导，写错编译报错 |
| ServiceError | services 抛类型化错误，框架统一映射（hx → 横幅片段，普通 → JSON），actions 零 try/catch |
| 代码生成 | 扫描页面树生成容器/服务/路由/壳，改声明自动重生成（`.elysiax/`，类 `.next` 模式） |
| 类型化路由 | `routes.pages.servers.ByIdCard(s.id)` —— 改路由时引用处编译报错 |
| client 逃生舱 | 页面目录放 `client/index.tsx` → 整页 Solid（框架自造插件 `@elysiax/solid` 预打包落盘，壳走 Bun HTMLBundle），JSON API 走 actions + Eden |
| defineRealtime | 进程内事件总线 + SSE，心跳/快照/断开自动退订 |
| 测试容器 | `createTestContainer(gen, { mock })` 一行起容器，override 换实现 |
| CLI | 脚手架、dev（codegen + hot + 结构变化重启）、doctor 体检、`bun build --compile` 桌面打包 |

## 一个页面长什么样

```
src/pages/
  index.page.tsx          # 首页（URL /）
  servers/                # URL /servers，API 前缀 /api/servers
    servers.page.tsx      # 整页（definePage → { title, content }）
    servers.partials.tsx  # hx 片段子路由（defineRoutes，GET 片段）
    servers.actions.tsx   # 写端点子路由（POST/DELETE，toast/redirect）
    servers.di.ts         # 服务声明
    servers.service.ts / servers.repository.ts
  deploy/                 # 纯服务模块：无 page/partials/actions，不进路由表
    deploy.di.ts
    deploy.service.ts
  canvas/                 # client 模式（L5 逃生舱）
    client/index.tsx      # 整页 Solid client，壳 HTML 由 codegen 生成
    canvas.actions.ts     # JSON API（/api/canvas/*）
    canvas.service.ts
```

规则：

- 没有 `.page.tsx` 的文件夹 = **纯服务模块**（只提供 DI，无路由）
- `[id]` 目录段 → `:id` 参数；下划线/点开头跳过；`client/` 是标记不进 URL
- partials/actions 挂载在 `/api<页面URL>` 前缀下
- `.controller.tsx` / `.ui.tsx` 旧约定已**废除**，codegen 检测到直接报错

## 页面三件套

```tsx
// servers.page.tsx —— 整页原子
export default definePage(async ({ di }) => ({
  title: "服务器",
  content: <ServerList servers={await di.get("serverService").list()} />,
}));

// servers.partials.tsx —— GET 片段（/api/servers/:id/card）
export default defineRoutes()
  .get("/:id/card", ({ di, params }) => <ServerCard server={...} />);

// servers.actions.tsx —— 写端点（POST /api/servers）
export default defineRoutes()
  .post("/", { body: serverForm }, async ({ di, body, toast }) => {
    await di.get("serverService").create(body);
    toast(`服务器「${body.name}」已添加`);
    return <ServerList servers={await di.get("serverService").list()} />;
  });
```

校验失败（typebox）由框架返回 **422 + 错误横幅片段**（AppLayout 的 responseHandling 允许 swap 422），非 htmx 请求仍是 JSON 422。

## 全局壳：AppLayout

全站唯一壳（L0）：`<html><head>`、导航、toast 容器。纯视觉边框，不查业务数据。

```tsx
// src/app.layout.tsx
export default defineLayout(({ title, content }) => (
  <html lang="zh-CN">
    <head>…</head>
    <body>
      <main id="main">{content}</main>
      <ToastRoot />
      <ToastScripts />
    </body>
  </html>
));
```

## 声明服务：provide / lazy

```ts
// user.di.ts
export default defineModule({
  provides: {
    userRepository: provide(UserRepository, ["db"]),  // 值服务（db 等）用字符串键
    userService: provide(UserService, [UserRepository, lazy(OrderService)]),
    //                                                ↑ 懒加载，Lazy<T> 参数专用
  },
});
```

- 键 = camelCase 类名，不一致会 warn（其他模块按键注入）
- InferDI 不支持双向 Lazy——跨上下文保持单向依赖，组合上移到页面/actions 层
- 页面树的 di 与纯服务模块的 di 一视同仁进拓扑排序

## 错误处理：ServiceError

```ts
// service：业务错误抛类型化错误（不写中文 Error）
if (!input.name.trim()) throw new ServiceError("用户名不能为空", 422);

// actions：预期错误用 status() 返回，绝不写 try/catch 回显
if (!target) return status(404, { error: "部署目标不存在" });
```

框架统一映射：`HX-Request` → statusCode + 错误横幅片段；普通请求 → JSON `{ error }`。子类化（DeployError/SshError）可区分错误类别，走同一映射。

## 类型化路由（routes.gen）

codegen 从路由表 + 字面量路由生成助手，hx-* / client fetch 都不写裸路径：

```tsx
hx-get={routes.pages.servers.ByIdCard(s.id)}
hx-post={routes.pages.servers.index()}
```

> **client 页（浏览器代码）必须 `import { routes } from ".elysiax/routes.gen"` 直接引文件**，不能引 `.elysiax` 桶文件——桶文件会把整个服务端图谱打进浏览器 bundle。doctor 会检查。

## client 模式（L5 逃生舱）

页面目录放 `client/index.tsx` → codegen 生成 `.elysiax/shells/<slug>.html`（`<div id="root">` + script）；装了 `@elysiax/solid` 时 client 入口被框架插件预打包成落盘的 `<slug>.client.js`，URL 由 `Bun.serve` 的 HTMLBundle 直接服务，整页归 Solid：

- 后端数据走 actions 的 **JSON 端点**（不是 hx 片段）
- 模态/抽屉在 client 内实现（事件总线 + Host 组件），不跨 htmx/client 边界
- **铁律：client 依赖链不得 import Node-only 包**（dotenv、bun:sqlite、node:*），Bun 浏览器打包会 500。共享逻辑抽零依赖模块

## 实时推送：defineRealtime

```ts
export const rt = defineRealtime<MyEvent>();

// actions（SSE 端点，25s 心跳、断开自动退订；snapshot 首帧即齐）
.get("/events/:id", ({ params }) => rt.stream(`res:${params.id}`, () => snapshotOf(params.id)))

// service / 轮询器
rt.publish(`res:${id}`, event);
rt.hasSubs(`res:${id}`); // 无观众就跳过昂贵的拉取
```

## CLI

```sh
elysiax init [dir]         # 从模板创建项目（页面形态）
elysiax new page orders    # 脚手架页面（page/partials/actions/di/service），自动重跑 codegen
elysiax new service auth   # 纯服务模块（di + service，无路由）
elysiax new client canvas  # 已有页面升舱 client 模式
elysiax dev                # codegen + bun --hot；页面结构变化自动重启，声明变化自动重生成
elysiax gen                # 手动重生成 .elysiax/
elysiax doctor [--db x.db] # 体检 12 项：DI 图、路由冲突、岛边界、插座门禁/纯度/只增不减、
                           #   数据层、端点 schema、schema 漂移（--db）、迁移只追加、错误约定
elysiax build [--desktop]  # 编译二进制 / webview 桌面应用
```
