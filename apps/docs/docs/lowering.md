# 逐级降级：人在环中的抽象流水线

> elysiax 的框架哲学。与 [原子分发哲学](./elysiax.mdx)、[模块契约](./module-contract.md) 并列——那两篇讲"代码怎么组织"，这篇讲"人、抽象、原料三者的权力关系"。

## 1. 世界分两层：抽象层 和 原料层

- **抽象**：人操作的东西。Tailwind 类名、TSX 组件、di 声明、socket 插座。
- **原料**：机器消费的东西。浏览器只认原始 HTML + CSS + JS，运行时只认注册好的路由和容器。

人写抽象，机器吃原料，两层永不混淆。

## 2. 两层之间隔着一道转换，这道转换不是人做的

```
人 ──写抽象──▶ 构建工具 / AI ──降级──▶ 原料
```

人永远不手写 CSS 文件，就像现代人不手写汇编。Tailwind 类名 → CSS 由构建工具完成；更复杂的抽象（"我描述桌面"→ 整页原料）由 AI 完成。

## 3. 核心约束：每一步的产物落在地上，人能直接判断

降级不是黑盒一口气跑完。**每一级产出真实文件**，落在磁盘上，人可以停下来看、改、否决：

- 人不下场写原料，但人**审查原料**；
- 产物是坐标点，不是管道里流过的水——`cat .elysiax/routes.gen.ts` 永远能看；
- 人手改过的产物，降级工具必须识别并尊重，不得覆盖（这是现有工具链都没做好的一步，是 elysiax 要占的位置）。

## 4. 笛卡尔坐标系：每个操作都有空间坐标

横轴抽象层级，纵轴产物形态。每个文件是坐标系里的一个点，每次转换是一条有向边：

```
(tailwind 类名, 源码) ──▶ (css, 产物) ──▶ (浏览器渲染)
(di 声明, 源码)      ──▶ (routes.gen.ts, 产物) ──▶ (运行时路由表)
```

操作不是混沌的，是可定位的。说"这一步"时，指的不是一团模糊的过程，而是图上确定的一条边。

## 5. 扩音器模型：人的权力不变，能力被放大

人对着扩音器说话：**说什么由人决定，机器只负责放大**。构建工具和 AI 是扩音器，不是替身。

人的角色从"写代码的人"上移为"**操作抽象、审查产物的人**"。自主 agent 路线（AI 替人做决定）是另一条路，不是这条。

## 6. 在 elysiax 里的既有落地

| 思想 | 落地 |
|---|---|
| 降级产物可见 | `.elysiax/` codegen 落盘成真实文件（routes.gen.ts、shells/*.html），可 cat 可 diff |
| 每步可判断 | `elysiax doctor` 十二项检查 = 人在降级链上的判断助手，装期报错而非运行时炸 |
| 抽象/原料分离 | 原子 = 纯抽象分发单元；构建时才降级出原料 |
| 产物坐标化 | 原子分发 = 复制一个坐标点，闭包完整、可单独摘走 |
| 构建链框架自造 | `@elysiax/solid`：框架自己的 Bun 插件把 client JSX 降级成纯 JS（落盘 `.elysiax/shells/*.client.js`），应用零配置；babel 内核是包内实现细节，可整体替换 |

## 7. 待占的位置

- **产物可手改且被尊重**：降级工具识别人工修改的区段，不覆盖、不静默回滚；
- **降级链可逆定位**：原料出问题，能指回是哪一级抽象的哪一条边产生的；
- **AI 作为降级器**：人描述意图（抽象），AI 产出原料，人在每一级审查——AI 是流水线里的一级转换器，不是流水线外的黑盒。

---

一句话：**人只操作抽象，抽象到原料的降级由工具/AI 完成，降级链上每一级产物都是真实文件、人可随时介入判断——工具放大人的意图，不取代人的判断。**
